## 索引变更记录（2026-06-04~05）

### 问题
`doc_chunks` 表 HNSW 索引缺失（handoff 误记 valid），导致向量搜索全表扫描 1.75M 行，耗时 27-30s。

### 尝试
1. **HNSW (4GB maintenance_work_mem)** — Docker shm_size 不够，报错
2. **HNSW (1GB)** — 速度 3000 tuples/s，跑到 37% 后内存耗尽 swap，速度降到 20 tuples/s，取消
3. **IVFFlat (lists=1323, 512MB)** — 成功！k-means 聚类 ~5min + tuple 分配 ~5min + 排序 ~10min

### 结果
| 索引 | 状态 | 大小 | 搜索延迟 |
|------|------|------|---------|
| `idx_doc_chunks_embedding_ivfflat` | ✅ valid | 4563 MB | 6ms |
| `idx_doc_chunks_search_vector_gin` | ✅ valid | — | — |
| `idx_guoxue_content_embedding_hnsw` | ✅ valid | — | — |
| `idx_corrections_embedding_hnsw` | ✅ valid | — | — |

### 注意
- Docker 容器已 `docker update --memory 8G`，但 **docker-compose.yml 仍是 4GB**，重启容器会丢失。需更新 docker-compose.yml。
- HNSW 比 IVFFlat 召回率更高（m=16, ef_construction=64），当前 IVFFlat 是资源受限下的临时方案。
- 未来内存充足后可切回 HNSW：`DROP INDEX idx_doc_chunks_embedding_ivfflat; CREATE INDEX ... USING hnsw ...`
